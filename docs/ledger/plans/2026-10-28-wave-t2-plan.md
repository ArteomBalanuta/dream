Purpose: split wave T2 of the day/night roadmap into one contract commit (C0) and six workstreams that own separate files.

Status: approved for implementation. The architect analysed `integrate/engine-iteration` at `951dc74` read-only. Persistence wave A runs in parallel and owns `Server/Persistence/*`, `Simulation/Persistence/*`, `config/*.sql`, the persistence part of `ServerBootstrap.cs` and `docs/server-persistence-ddl.md`. No T2 workstream touches those.

## Corrections To The Roadmap

These come from reading the code.

1. **Remote equip state is not replicated.** `ActorSnapshot`, its delta format (`ActorReplicationFrame` / `ActorFrameJson`) and `RemotePlayerPresentationState` carry no item. Only the owner receives its `PlayerInventorySnapshot`. Showing another player's torch light therefore needs a protocol change, which is the new workstream T2f (protocol v6).
2. **There is no building menu.** `BuildUseIntent(PlacementTarget)` carries no material. The server uses the material of the supporting cell (`ResolveBuildPlacementMaterial`). T2c adds a `build.material` action the client can send, plus a small HUD panel.
3. **Persistence needs no changes.**
   - `material_id` is stored as text and parsed with `Enum.Parse(ignoreCase: true)`, so `"Lamp"` round-trips.
   - `item_kind` is stored as text. On load, `ToolCatalog.Resolve` must know the kind, so `tool.torch` is added to the catalog.
   - An older build cannot open a database that contains a torch. Downgrading is not supported.
4. **Adding `GeometryMaterialId.Lamp` on its own breaks tests that enumerate materials.** The enum value therefore stays out of C0; T2c owns it together with its catalogs.
5. **Existing players don't receive new starter items,** because starter items are only seeded into an empty backpack. T2b appends the torch as the last starter item and adds a one-time top-up of missing starter items. The existing `tool.survey-lantern` gets a weaker light.
6. **The night wolf is persisted** like any other enemy. When it is removed at dawn, the next checkpoint diff deletes its row.
7. **`AnimatedModel` already sets `material.emissiveFactor`,** but no shader declares it yet.

```csharp
// LightCollector.cs — filled by the scene each frame before DrawWorld; never allocates after construction.
namespace Dream.Rendering.Lighting;
public sealed class LightCollector
{
    public const int Capacity = 1024;
    private readonly PointLight[] _lights = new PointLight[Capacity];
    public int Count { get; private set; }
    public int Dropped { get; private set; }
    public ReadOnlySpan<PointLight> Lights => _lights.AsSpan(0, Count);
    public void Clear() { Count = 0; Dropped = 0; }
    public void Add(in PointLight light)
    {
        if (!(light.Radius > 0f) || !float.IsFinite(light.Radius) || !float.IsFinite(light.Position.X)
            || !float.IsFinite(light.Position.Y) || !float.IsFinite(light.Position.Z)) return;
        if (Count == Capacity) { Dropped++; return; }
        _lights[Count++] = light;
    }
}
```

```glsl
// pointLights.glsl — `#include "pointLights.glsl"` after lighting.glsl (one level, no #version).
// Mirrors Rendering/Lighting/LightList.cs (std140, 528 B, binding LightList.BindingPoint = 1).
// World range: world-space positions. View-model range: eye-space positions (view model draws with view = identity).
layout(std140) uniform LightList {
    ivec4 uPointLightCount;               // x = active lights, 0..16
    vec4 uPointLightPositionRadius[16];
    vec4 uPointLightColor[16];
};
vec3 dreamPointLights(vec3 n, vec3 fragPos) {
    vec3 sum = vec3(0.0);
    for (int i = 0; i < uPointLightCount.x; ++i) {
        vec3 toLight = uPointLightPositionRadius[i].xyz - fragPos;
        float r = uPointLightPositionRadius[i].w;
        float d2 = dot(toLight, toLight);
        float f = clamp(1.0 - d2 / (r * r), 0.0, 1.0);
        f *= f;
        float lambert = max(dot(n, toLight * inversesqrt(max(d2, 1e-4))), 0.0);
        sum += uPointLightColor[i].rgb * (f * (0.25 + 0.75 * lambert)); // 0.25 wrap keeps faces readable
    }
    return sum;
}
```

### T2a: Point lights

**Owns:**
- `PointLight.cs`, `LightList.cs`, `LightCollector.cs`, `pointLights.glsl`.
- New `Rendering/Lighting/LightListBuffer.cs`: a world range at 0 and a view-model range at `RoundUp(528, UniformBufferOffsetAlignment)`; `BindProgramBlock`, `Upload`, `BindWorld`, `BindViewModel`.
- New `Rendering/Lighting/LightSelection.cs`: a pure `SelectNearest(ReadOnlySpan<PointLight>, Vector3 camera, in ViewFrustum, ref LightList)`.
  - Culls with `frustum.IntersectsBox(pos, new Vector3(radius))`.
  - Keeps the 16 nearest by squared distance. Ties keep input order, so lights don't flicker.
  - Uses a fixed 16-slot insertion, so nothing is allocated for sorting.
- `Render.PointLights.cs`.
- `Render.Lighting.cs`:
  - `InitializeFrameLighting` and `DisposeFrameLighting` create and dispose the `LightListBuffer`.
  - `UploadFrameLighting` also builds the frustum and selects and uploads the lights (one more uniform upload per frame).
  - `BindWorldLighting` and `BindViewModelLighting` bind both blocks' ranges.
- `Shader.cs`: one `LightListBuffer.BindProgramBlock(program)` call next to the `FrameLighting` call.
- `cubeFragment.glsl` and `enemyFragment.glsl`:
  - include `pointLights.glsl`;
  - cube: `(dreamAmbient(n) + dreamDirect(n) + dreamPointLights(n, fragPos)) * base`;
  - enemy: `(dreamAmbient*z + (dreamDirect + dreamPointLights) * ActorDirectScale) * base`, then the floor.
- `lighting.glsl` and `Render.Shaders.cs`, only if needed.
- `WorldShaderContractTests.cs` and `Wave9AlphaMaskUniformCoverageTests.cs`, only if needed.
- The debug variable `DREAM_DEBUG_POINT_LIGHTS` (client, default 0, clamped to 0–64). It adds a deterministic ring of synthetic lights around the camera, for the perf harness.
- The view-model range transforms light positions by the view matrix with `TransformPosition`, following the row-vector convention of `FrameLightingBuffer`.

**Tests:**
- `Unsafe.SizeOf<LightList>() == 528`, with fields at offsets 0, 16 and 272.
- Parsing the GLSL block gives the same fields as the C# struct, and the GLSL array size equals `MaxLights`.
- Selection:
  - picks the nearest 16;
  - culls a light behind the camera unless its sphere reaches into the frustum;
  - is stable on ties;
  - never writes a `Count` above 16;
  - handles 0 and 1,024 candidates.
- Collector: capacity, `Dropped`, and rejection of non-finite or zero-radius lights.
- Collecting, selecting and the view-model transform allocate 0 B over 1,000 frames.
- A CPU mirror of `dreamPointLights` gives f = 1 at distance 0 and 0 at distance ≥ r.

**Accepted when:**
- With 0 lights, the look is identical to T1 (cube noon within 1e-4).
- Draw calls are unchanged and uniform uploads go up by 1.
- With `DREAM_DEBUG_POINT_LIGHTS=16` and 2 clients in the harness: FPS stays at the cap, the World GPU section grows by at most 0.5 ms, and there are 0 GL errors.

**Spawn rule.** It runs on the authoritative side only, inside the existing `allowGameplaySimulation` block, once per tick:
- The target is 2 wolves when `WorldClock.Phase == Night`, otherwise 1.
- If fewer wolves are active than the target, spawn one: at the day spawn when none is active, otherwise at the night spawn.
- If it is not night and more than one is active, remove the active wolf with the highest actor id.

**Determinism:**
- The clock is derived from ticks only: the persisted world ticks, `TicksPerDay` and the tick count. From now on these three are lockstep inputs, and `WorldClock.cs` and the docs say so.
- `Advance()` runs before gameplay in `AdvanceAuthoritativeTick`.
- The checksum formula is unchanged. The extra wolf already shows up in the actor count and ids that are hashed.
- Rewrite `TwoPersistentServers_WithDifferentClocks_StayInLockstep` so both clocks stay in Day for the whole run. Add tests:
  - Day vs Night servers diverge on the first tick, by exactly one wolf.
  - Two equal night clocks crossing 20:00 and 04:00 are identical on every tick, with the spawn and the despawn on the same ticks.
  - A restart in the middle of the night restores 2 wolves and spawns no third.
  - A crash after the dawn despawn but before a checkpoint restores 2 wolves, and one is removed on the first tick.
  - The client runtime never runs the night step.
- The whole-day allocation test asserts 0 B on every tick except the single spawn tick and the single despawn tick.
